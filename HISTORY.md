# HISTORY

2026-10-18 — Forked at v0.1.2; peer widened, webRuntime dropped, settings reads hardened. ADR-001, ADR-002.
2026-10-18 — Wheel input fixed in the sidebar panel: a wheel over the letterbox bar was dropped (null mapping) and the canvas listener missed wheels when an overlay sat above it. Now clamps to the page and also listens on window in capture phase.
2026-10-18 — Fit-to-pane: the panel no longer letterboxes the page. It fits the page WIDTH (so a wide fullscreen pane gets a larger page, not black bars) and the canvas grows to the scaled page height, clipped by the viewport, so page scrolling still reaches every part.
2026-10-18 — Stale panel after navigation: when the shown tab's URL changes the client drops the stale bitmap and re-issues screencast.start (idempotent per target), instead of waiting for a close-and-reopen.
2026-10-18 — `forbidden` / no routes: the fork hardcoded an empty trusted-host list when `webRuntime` was dropped, so reaching DSH through the tailnet name (Host = dsh.komodo-everest.ts.net, not loopback) refused every live-view ticket. `trustedHosts` is now a config field, defaulting to loopback-only.
2026-10-18 — Three panel defects fixed: the Interactive input master switch now defaults ON (the per-view checkbox still starts unchecked, so a fresh view stays view-only) because default-off made the feature undiscoverable; auto-selection prefers a real page over chrome://newtab, which never repaints and read as a broken panel; target switching is serialised, since an overlapping `screencast.start` let `detach()` land while `Page.enable` awaited its reply, surfacing as "Protocol error (Page.enable): Target closed".
2026-10-18 — Inert panel root cause: the status overlay was `position:absolute; inset:0` with no `pointer-events:none`, so any transient status ("loading", "hidden", a stale error) covered the canvas and swallowed every click and wheel before the input bridge saw them. The overlay is now click-through, with `pointer-events:auto` restored on its Retry button.
2026-10-18 — Ticking "Keyboard & mouse control" failed with "target lease is held by another owner": the gate toggle closes the old socket and opens a new one with a fresh owner id, and releasing the old lease races the new acquire. A conflicting lease on this session's own target is now reclaimed instead of refused.
